## 4. Exact Workers Route configuration

Worker name: `bringas-seo-status`

| Setting | Route 1 | Route 2 |
|---|---|---|
| Attach type | **Route** (never *Custom Domain*) | **Route** |
| Zone | `bringasinsurance.com` | `bringasinsurance.com` |
| Route pattern | `bringasinsurance.com/*` | `www.bringasinsurance.com/*` |
| Failure mode | **Fail open** | **Fail open** |
| Requires | apex A record Proxied | www A record Proxied |

*Route* keeps Lovable as the origin so the Worker's `fetch(request)`
pass-through reaches the real site. *Custom Domain* would make the Worker
itself the origin, detach Lovable, and break every pass-through. Fail-open
means a Worker exception falls back to normal origin traffic — the site can
never go dark because of the Worker.

## 6. Migration checklist

**Phase 0 — approval (you are here)**
1. Export the GoDaddy zone file and diff it against §1.1. Approve or correct
   the inventory. *Nothing else starts until this is signed off.*
2. Note the current TTLs. Optional but recommended: 24 h before the switch,
   lower the apex/www A TTLs at GoDaddy to 600 s (they already are) so a
   rollback propagates fast.

**Phase 1 — build the Cloudflare zone (zero production impact)**
3. Create a free Cloudflare account; **Add a site** → `bringasinsurance.com` →
   Free plan. Cloudflare auto-imports what it can scan.
4. Compare the imported list against §1.1 and the GoDaddy export. Add anything
   missing. Verify byte-for-byte: MX value + priority `0`, the full SPF string,
   the complete `_lovable` token.
5. Set proxy status: apex A **Proxied**, www A **Proxied**, `autodiscover`
   CNAME **DNS-only**, MX/TXT DNS-only (forced).
6. Set SSL/TLS → **Full (strict)** and Always Use HTTPS → On.
7. Cloudflare shows two assigned nameservers. **Do not change GoDaddy yet.**

**Phase 2 — pre-flight verification against the not-yet-live Cloudflare NS**
8. Query the Cloudflare nameservers directly and confirm they already return
   the correct answers (replace `NS1` with your assigned nameserver):
   ```sh
   for q in "A bringasinsurance.com" "A www.bringasinsurance.com" \
            "MX bringasinsurance.com" "TXT bringasinsurance.com" \
            "TXT _lovable.bringasinsurance.com" \
            "CNAME autodiscover.bringasinsurance.com"; do
     echo "== $q"; dig +short $q @NS1.ns.cloudflare.com
   done
   ```
   Every answer must match §1.1. **If anything is missing, stop here** — this
   is the last risk-free checkpoint.

**Phase 3 — cut over (the only irreversible-feeling step; it is reversible)**
9. At GoDaddy: Domain → Nameservers → **Change** → *I'll use my own* → enter
   the two Cloudflare nameservers → save. Propagation is typically 5–60 min.
10. Watch Cloudflare's dashboard until the zone shows **Active**.
11. Verify from the public internet:
    ```sh
    dig +short NS bringasinsurance.com
    dig +short MX bringasinsurance.com
    curl -sI https://bringasinsurance.com/ | head -1
    ```
12. **Send a live test email** to a mailbox on the domain and reply out from
    it. Do not proceed until inbound and outbound mail are both confirmed.

**Phase 4 — deploy the Worker**
13. Follow the 9 dashboard steps in `docs/edge-redirects.md`
    ("Cloudflare dashboard deployment steps"), using the routes in §4 above.
14. Purge cache (Caching → Configuration → Purge Everything).
15. Run the validation block in §8.

**Phase 5 — post-deployment**
16. In Google Search Console, re-submit `https://bringasinsurance.com/sitemap.xml`
    and request validation on the "Soft 404" and "Crawled – not indexed" issues.
17. Optionally add DKIM + DMARC as a separate, later change.

## 7. Rollback plan

| Failure | Rollback | Time to recover |
|---|---|---|
| Worker misbehaves (wrong 404/410, page breaks) | Worker → Settings → Domains & Routes → **delete both routes**. Traffic returns to plain origin behaviour instantly. Nothing in the Lovable project changes. | Seconds |
| SSL loop / "too many redirects" | SSL/TLS → set **Full (strict)** (a loop means it was left on *Flexible*). | ~1 min |
| Site down after proxying | Toggle apex/www to **DNS-only (grey cloud)**. The site serves directly from Lovable exactly as today; the Worker Route simply stops firing. | ~1 min |
| Email broken after cutover | Fix the MX/SPF record inside Cloudflare (fastest — 300 s TTL). Only if that fails, do the full rollback below. | 1–5 min |
| Anything unrecoverable | At GoDaddy: Nameservers → **Change** back to `ns77.domaincontrol.com` and `ns78.domaincontrol.com`. GoDaddy retains the original zone, so all records return as they are today. | 5–60 min propagation |

Safety properties: the Cloudflare zone is built and verified *before* the
switch; the nameserver change itself is a one-field, fully reversible edit at
GoDaddy; and Fail-open routing means a broken Worker degrades to today's
behaviour rather than an outage.
